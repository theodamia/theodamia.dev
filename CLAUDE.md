# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Personal portfolio website for Theodore Damianidis (theodamia.dev). "The Ascent": ten years of software engineering drawn as one long climb. Three routes. `/` is the hero plus the climb: a sticky, scroll-driven painted scene the camera walks into, one card per job, and a summit that is deliberately never reached. `/cv` is the same ten years read plainly — a field log of every job newest first, then contact — for whoever wants the facts rather than the walk, while the year turns behind it in the valley at the foot of the climb's mountain. `/about` is the summit's page, "what's ahead": it opens on the sky at the visitor's time of day, reads plainly (About, How I work, Skills), and ends at Contact on the next range across a sea of clouds, where the sun comes up as the last screen scrolls in. A floating icon dock at the bottom is the only navigation and works across all three; it ends with the day/night switch.

The visual language is "Alpine": a cool, white, precise interface (slate ink, hairline borders, one orange accent) sitting on a green, sunny, painted mountain. By night ("Alpine night") the same tokens turn to dark slate and pale ink, and the mountain is moonlit under stars. Green belongs to the scene, never to the interface. The frozen design reference lives in Claude Design (`The Ascent v4`); changes now happen in code.

- `pnpm vitest run components/__tests__/dock.test.tsx` - Run a single test file

## Architecture

- **Framework**: Next.js 16 App Router, React 19, TypeScript (strict mode)
- **Styling**: Tailwind CSS 4 with `cva` for variants. All design tokens live in `@theme` in `app/globals.css` — colours, the two font families, radii, shadows, easing, keyframes. The `@theme` values are the day; the night overrides the same tokens under `:root[data-theme='dark']`, so components never carry two sets of colours. `dark:` is a custom variant on `data-theme` (not the system setting), for the few element-level changes. `touch:` and `touch-wide:` are custom variants for screens that cannot hover (`touch-wide` is 360px and up, where the dock's lit item has room to spell out its name). The one page breakpoint is the `--breakpoint-wide: 900px` token: `wide:` and `max-wide:` in markup, `WIDE_QUERY` in `constants/` for the same line in JS. A `--shadow-*` value is inlined into its utility by Tailwind, so the night's shadows flip through a `--shadow-cast-*` colour instead
- **Type**: Bricolage Grotesque (display; loaded variable with its `opsz` axis, the big headings need the narrow display cut) and Instrument Sans (text), via `next/font/google` in `app/layout.tsx`
- **Scene**: whole paintings (WebP), moved with CSS transforms and opacity. No WebGL, no canvas, no chart or animation library. `scene/` is the climb as numbers (the camera, the paintings' manifest); `components/scene/ascent-stage.tsx` renders and moves it. The paintings are made by an image model from the prompts under `art/` and processed by the scripts under `scripts/`
- **Testing**: Vitest + React Testing Library + jsdom
- **Linting**: `eslint-config-next` (Next, React, React Hooks v7 with the compiler rules) plus the full `jsx-a11y` recommended set as errors and `typescript-eslint`'s type-aware rules on TS/TSX, which is what catches a promise nobody awaits. `eslint.config.mjs` adds rules to the plugins Next already registers, never the plugins' own flat configs
- **Pre-commit**: Husky runs lint-staged (ESLint fix + Prettier on TS/TSX/JS/JSX, Prettier on JSON/MD/CSS). It does not match `.mjs`, so a changed script is checked only by `pnpm check` (or `npx eslint scripts/`)

### The scene boundary

Everything outside `components/scene/` knows the climb through two things only, so the stage can change (or be replaced) without touching cards, dock or altimeter. The painted look is the chosen one: a generated SVG mountain and a 3D low-poly renderer were both built and retired, so "more alive" means painted, in-world touches on these paintings, never interface effects laid over them:

- `scene/world.ts` — the climb as numbers: the stops (`CAMP_COUNT`, `CAMP_YEARS`), how long each leg is (`LEG_WEIGHTS`), where the altimeter's rail puts a point (`railShare`), which side each card stands on (`SIDES`), and the frame types. Pure maths, so it runs on the server and in jsdom
- `SceneHandle` (`applyFrame(frame)`, `resize(layout)`) — the stage implements it; `hooks/use-climb-scroll.ts` is the only caller

### Directory Layout

- **A folder is named for what its contents are _about_.** `content/` is the CV and every word on the site; `scene/` is the climb and the backdrops as numbers; `components/`, `hooks/`, `app/` are what they say. `lib/` is the narrow one: **where our code meets someone else's** — Next's Metadata API, view transitions, the browser's image decoding, storage, schema.org. `utils/` is the deliberate exception to the naming rule: generic, domain-free helpers, whatever they happen to import — `cn()` wraps two packages and still belongs there, because you look for it under "how do I merge class names", not under "what does it depend on". Sorting by dependency instead would put `cn` next to the metadata adapter and the camera maths next to a string trimmer, which helps nobody find anything
- `app/` - `layout.tsx` (fonts, metadata, the three `<head>` scripts, the dock), `page.tsx` (`/`), `cv/page.tsx` (`/cv`), `about/page.tsx` (`/about`), `globals.css`, `opengraph-image.tsx` (the share card)
- `components/` - One file per piece: `climb.tsx` (the main page's client shell), `scenery.tsx` (the closing card's set-aside state, shared by the card and the cairn), `trail-link.tsx` (every link between the pages: it moves up or down the mountain), `field-log.tsx` and `log-entry.tsx` (the log on `/cv`: the rail, and one entry on it), `hero`, `job-card`, `closing-card`, `altimeter`, `scroll-cue`, `dock`, `dock-bubble`, `theme-toggle`, the pieces of `/about` (`about-hero`, `about-section`, `opinion-list`, `week-bar`, `skill-columns`, `about-finale`, `contact-signal`: the easter egg's trigger), and what pages share (`page-header`, `section-card`, `fact-item`, `contact-rows`, `copy-email-button`, `social-links`)
- `components/scene/` - `ascent-stage.tsx` (the climb's stage; it carries `.scene-stage`), `scene-flat.tsx` (one painting the stage moves as a layer, with its flag), `snow-layer.tsx`, `cairn.tsx` (the way back to the closing card), `aurora.tsx`, `sky.tsx` (the sky's gradients, the stars, the shooting stars, the clouds and `Celestial`, the sun that becomes the moon; `PaintedClouds` carries the climb's clouds into the still pages), `theme-picture.tsx` (one painting in both themes as CSS backgrounds, for the still pages), `year-backdrop.tsx` (the year behind `/cv` on wide screens), `year-fade.tsx`, `year-weather.tsx` and `year-ready.tsx` (its turn, its weather, its loading), `about-dawn.tsx` (`/about`'s ending: the range, the sun, the saucer)
- `components/icons/` - Inline SVG icons. The dock uses `lucide-react` (Tent, Map, NotebookPen, RadioTower) at stroke 1.75 (`DOCK_ICON_STROKE`). `brand-icon.tsx` holds the three Simple Icons glyphs, and its `BrandIcon` also draws the skills' logos, whose paths come from the `simple-icons` package (server-only, so it never reaches the client). A skill with no logo (a practice) gets a Lucide symbol instead; the pairing lives in `content/skill-groups.ts` (`brand` or `icon` per skill), and both render in `accent-text`, the one touch of colour in the section
- `components/ui/` - Small primitives. `button` holds two class recipes rather than components, since almost every button is a link: `buttonVariants` and `quietLinkVariants` (the dotted link between pages and under a button; `standalone` when it is not inside a sentence). `text` holds `Heading`, `Eyebrow` and `Lede`; `Heading` and `Eyebrow` take `as`, so the tag follows the document and the look follows the variant
- `components/__tests__/`, `content/__tests__/`, `lib/__tests__/`, `scene/__tests__/`, `utils/__tests__/` - Tests colocated in `__tests__` directories
- `hooks/` - `use-climb-scroll.ts` (scroll controller), `use-in-view.ts` (one IntersectionObserver, no per-frame work), `use-reduced-motion.ts`, `use-theme.ts` (the theme on `<html>`, and following the system until someone picks)
- `constants/index.ts` - **Only what two or more modules share, or what must match `globals.css`**: the section scroll offset, the dock's icon stroke and the three media queries (`WIDE_QUERY`, `REDUCED_MOTION_QUERY`, `DARK_SCHEME_QUERY`). A value a single module uses lives with that module — `STAR_FIELD` in `scene/stars.ts`, `LEG_WEIGHT` in `scene/world.ts`, `THEME_REVEAL` in `lib/theme.ts` — because a number kept far from the arithmetic that reads it is a number nobody can check, and because this file otherwise becomes a drawer. Likewise a name only its own module reads is not exported
- `utils/` - Our own helpers, one per file, named for what it does — don't add a catch-all `utils.ts`. `cn.ts` (clsx + tailwind-merge), `time-at-progress.ts` (inverse of a cubic-bezier easing), `bare-url.ts` (a URL as a CV prints it), `climb-stops.ts` (where each stop sits on the page — out of the scroll hook so the one piece of arithmetic the whole climb rests on can be tested on its own)
- `lib/page-metadata.ts` - One page's metadata, share card included. **Next resolves `openGraph` per segment and does not merge it field by field**: a page that writes its own replaces the root's whole object and silently takes the generated card with it, so it would be shared as the home page, or as a bare text card. Every page below the root goes through `pageMetadata()` for that reason. `metadataBase` (from `SITE.url`) is what makes the relative canonicals and the card URL resolve
- `lib/theme.ts` - Day and night: the no-flash `<head>` script, reading and storing the choice, and `switchTheme()`, the reveal
- `lib/scene-art.ts` - Loading the climb's paintings (below). `lib/view-morph.ts` - `morph()`, one thing on the page carried into another by a view transition (the closing card into the cairn). `lib/person-schema.ts` - the JSON-LD `Person` on `/`, derived from `content/` so it cannot drift
- `app/opengraph-image.tsx` - The card a recruiter sees when the link is pasted into LinkedIn or Slack: the same four facts as the hero, over the same dawn and hills, generated at build so it can never drift from `content/site.ts`. Satori is not a browser (no `oklch`, no CSS variables, no `clip-path`, and every box with more than one child needs an explicit `display: flex`), hence the plain hex and the hills as one `<svg>`. Its two fonts are committed under `lib/og/fonts` (OFL) so a build never reaches the network
- `content/` - `jobs.ts`, `skill-groups.ts`, `about.ts`, `site.ts`, `dock-items.ts`. All page content. Nothing is fetched; edit the CV here, not in JSX
- `scene/` - `world.ts` (above), `camera.ts` (the forward climb's camera), `flats.ts` + `flats.json` (the climb's paintings), `seasons.ts` + `seasons.json` (the year behind `/cv`), `about.ts` + `about.json` (`/about`'s range and saucer, and its time of day), `stars.ts`, `snow.ts` and `noise.ts` (the generated sky: integer hashing, no `Math.random`, no trigonometry, so server and browser write the same markup). The `.json` files are written by the scripts, never by hand
- `scripts/` - The art pipelines: `process-flats.mjs` (`pnpm flats`), `compose-flats.mjs` (`pnpm flats:compose`), `process-seasons.mjs` (`pnpm seasons`), `process-about.mjs` (`pnpm about`), `process-icons.mjs` (`pnpm icons`: TD in trail paint on granite, by day and by moonlight, framed on the letters so it reads at 16px; `art/icon/README.md`). What every painting goes through is shared: `flat-key.mjs` keys the magenta out, `paintings.mjs` does the rest (loading, specks, repairing the colour along the outline, despill, bounds, the bleed under transparent pixels, WebP, content-hashed files, a manifest formatted by the repo's Prettier), and `scene-token-rgb.mjs` reads a scene token out of `globals.css`, so the far ranges are hazed toward the very colour the page fills under them. A rebuild of unchanged paintings is byte-identical: check `git status` after touching a script
- `art/` - The prompts and the record of every painting, per page (`art/scene/`, `art/cv/`, `art/about/`, `art/icon/`), each with a README. The raw paintings stay local (`.gitignore`) and are the only copies: back them up
- `test/setup.ts` - Global test setup and mocks (Next.js router, browser APIs)

### Key Conventions

- Path alias: `@/*` maps to project root (e.g., `@/components/dock`, `@/utils/cn`)
- Components use named exports (`export function Component()`), pages use default exports
- Server Components by default; `'use client'` only where something runs in the browser: the climb's shell and stage, the closing card and the cairn, the aurora, the dock and its switch, trail links, the copy button, `/cv`'s weather and loading, `/about`'s contact signal. The generated sky (stars, snow) is computed once per module from integer noise, so the server and the browser agree on it
- File names: kebab-case. Component names: PascalCase
- Prettier: single quotes, JSX single quotes, semicolons, 2-space indent, 100 char line width, trailing commas (es5)
- Blank lines are the one thing Prettier leaves alone, so ESLint sets them (`@stylistic/padding-line-between-statements`): one before every `return`, one on each side of an `if`/`for`/`while`/`try`/`switch`, and one after the imports and any directive. `eslint --fix` writes them for you
- Use `cn()` for conditional/merged Tailwind classes
- Use `cva` (class-variance-authority) for component variants
- **A branch that does work gets braces.** A one-line `if` is only for a guard that _leaves_ — `return`, `throw`, `continue`, `break` — where the condition and the exit are both in view. `if (cond) doThing();` is not allowed: the side effect hides at the end of a line you were reading for the condition. An `else` always takes braces. Enforced by three `no-restricted-syntax` selectors plus `@stylistic/nonblock-statement-body-position`. **It cannot be the `curly` rule** — `curly` counts statements and measures lines but never looks at what kind of statement the body is, so `"all"` would flag every guard in the codebase and `"multi"`/`"multi-line"`/`"multi-or-nest"` wave `if (x) doThing();` through exactly as readily as `if (x) return;`. Don't swap it in. It covers everything we write, `scripts/` included: the pixel loops there are mostly `continue` guards, which the rule allows, so the build tool is held to the same standard as the app
- **JSDoc every exported function, and say why rather than what.** A `/** */` above the export, in the voice the rest of the file uses: what the thing is for, what a reader would get wrong, what was tried and rejected. There is deliberately no lint rule for it — a linter can only check that a comment exists, which is how you get comments written to satisfy a linter. Skip it where the name genuinely says everything, and never write one that only restates the signature
- Avoid nested ternaries; extract to variables or early returns
- Extract magic numbers into named constants
- Add a token in `@theme` rather than hardcoding a colour in JSX, and give it a night value under `:root[data-theme='dark']` unless it is the same in both (no `white` or `rgb(30 43 55 / …)` literals, except white text on the accent: text on an ink fill is `on-ink`, a shadow or hole is `shade`)
- **The frame rule.** While scrolling, write only `transform` (pixels, snapped to the device pixel grid) and `opacity`, on whole layers, and each only when it changes. No CSS variables feeding `calc()`, no layout reads, no attribute changes, no React state per frame. Everything that needs layout is read in `measure()` (resize and `ResizeObserver` only). This is what keeps the climb smooth — keep it intact if you touch `use-climb-scroll.ts` or `ascent-stage.tsx`. Anything the still pages move with the scroll is a CSS scroll-driven animation instead (`/cv`'s year, `/about`'s sunrise, the closing card's `.rise-in`), behind `@supports (animation-timeline: view())`
- Elements the stage moves per frame get their resting pose from the `transform` property (`[transform:…]`), never from Tailwind's translate utilities: those set the separate `translate` property, which would add to the per-frame transform instead of being replaced by it
- Anything that animates inside the scene is a small layer of its own (the pennant, a camp's name, the summit line, the cairn), never part of a painting's layer, so it repaints only itself. Keyframes run on `transform` and `opacity` only, with plain numbers
- **Long cycles.** The browser wakes the main thread whenever a CSS animation's cycle ends, so short cycles on many elements cost a style recalc nearly every frame. The generated keyframes (stars, snow, `/cv`'s weather) carry each thing across many times per cycle instead

### The forward climb

- **Flats.** The climb is a stack of whole paintings, back to front: the far ranges with the cloud sea (`back`, a seamless tile), the peak, and six ridge shoulders (`camp`), the trailhead village plus one per job, each with its camp painted in. Each has a day and a night painting with one outline. `scene/flats.json` lists them with their boxes in design units (one unit is one pixel at 1440 × 900), the solid spans and skylines measured on the paint, where each camp's flag and name go, and today's cairn
- **The camera** (`scene/camera.ts`, pure maths, the design system's camera sheet). Scrolling walks the camera forward along the route. Every flat sits at a depth, and its scale is `p = 1 / (its depth − the camera's)`: exactly 1 when the camera stands at its stop. Every point lands at `focus + p · v · (its offset from the focus)`, the focus of expansion being the foot of the peak, so the route converges below the summit and no ridge ever covers it. A ridge fades in far ahead as its far version (smaller, softer, hazed), sharpens into its near one as the camera approaches, and fades out once passed (`LIFE`). The peak and the far ranges come closer but are never reached. Long jobs sit deeper (`DEPTH_PER_WEIGHT`), so the camera keeps one speed. The camera never bends to fit a screen: a wider one sees more world, so the backdrop repeats sideways (`BACKDROP_TILES`) over a haze fill, and the trailhead is painted with bleed (`FILLED_ASPECT`, `PAINTED_ASPECT`; `art/scene/README.md`, "Any screen"). `poseAt(u, view)` is one moment of the climb, everything the stage writes; `skyAt()` says whether a point of the screen is open sky, from each painting's skyline
- **The stage** (`components/scene/ascent-stage.tsx`). Back to front: the sky (dawn by day, dusk by night) and the daylight that fades in over it as the climb goes on (midnight by night), the stars and the shooting stars, `Celestial`, the aurora, the clouds, the flats, the snow, the camps' names, the summit line. A flat's box is authored at the largest it is ever shown (`HEADROOM`) and sized in CSS from the stage scale `--v`, so the stage only ever scales down. Reduced motion: the scene changes between stops under a short veil in the sky's colour, never by moving
- **Loading the paintings** (`lib/scene-art.ts`). Every painting is an `<img data-art="day|night">` with no `src`, carrying `data-src` and, for near paintings, `data-src-phone` (the middle a phone sees, `usesPhoneArt()`: not the 900px breakpoint, a phone on its side sees far more). The source is picked once for the screen the visit starts on, and nothing is shown until its own `decode()` has finished (`data-ready`), so nothing is ever drawn half-decoded mid-scroll and a file that fails simply never appears. The climb holds still until the first view's paintings are decoded (`FIRST_POSE`); the rest of the theme follows at low priority, the other theme when the browser is idle. Only the theme on screen is displayed, and until its painting is ready the other theme's stands in: never a hole. `pnpm flats` prints the bytes a visit costs against the budget (1500 KB desktop, 800 KB phone, per theme)
- **Arrival.** When `use-climb-scroll` reports a new stop, that camp's flag runs up (one painted flag shared by every job camp, placed in each ridge's box so it scales and fades with it; the pennant is a layer of its own, `.scene-pennant[data-reached]`) and its name brightens (`.scene-label[data-reached]`). **A camp never changes colour or size.** Names are shown only for the camp at hand and the next one
- Every stop is a job, but the trail starts lower: camps are waypoints, `[TRAILHEAD, ...JOBS]` (`CAMP_COUNT = JOBS.length + 1`). Camp 0 is the trailhead (the village, no card, "Start" on the altimeter, always reached); job `i` stands at camp `i + 1`. Legs are sized by **compressed tenure** (`legWeight(years)` in `scene/world.ts`, limits in `LEG_WEIGHT`): the same weight sets how deep the next camp stands and the `min-height` of that job's `<li>` (`LEG_SCROLL_LVH` in `climb.tsx`), so long stays scroll longer and the camera keeps one speed. It is deliberately not proportional to years (a six-month job would be a sliver no card fits in) and not calendar-based (gaps between jobs never show). Adding or removing a job in `content/jobs.ts` re-sizes the legs, the cards and the rail on its own, but a camp is a painting: a new job also needs its ridge painted and listed in `FLATS` in `scripts/process-flats.mjs` (its id is `camp-<start year>`; `art/scene/README.md`, "Painting a new piece")
- **The top of the climb.** The summit line, `SUMMIT_LINE` ("The peak is still ahead"), comes in over the last stretch and fades when the closing card comes up. The closing card rises into place as it enters the view. "Take in the view" sets it aside: it shrinks into a cairn by the path above today's camp (`lib/view-morph.ts`, the `card-in`/`card-out` view transitions), kept there like a note under a stone, and the cairn (a real button, "Today's note") brings it back out. The card keeps its place in the page while set aside (hidden and inert), so the page's length and the climb's last stop never move. The state lives in `components/scenery.tsx`, owned by the climb, because both ends live there
- **The sky's motion and the snow.** The climb has no seasons: one sky, day or night (`/cv`'s year is its own, below). The sky is alive on its own, all compositor work: painted clouds carried left to right by a steady wind and billowing (`CLOUD_WIND` in `components/scene/sky.tsx`), stars that scintillate by night with rays on the brightest (`scene/stars.ts`), two rare shooting stars, and the snow of the heights (`scene/snow.ts`, `components/scene/snow-layer.tsx`), which the camera fades in from the Lead camp (`SNOWLINE_CAMP`) and thickens toward the summit, one opacity per layer per frame. Below the snowline the green meadows get no weather. Reduced motion: no snow, no twinkle, the clouds stand still
- **The aurora** (`components/scene/aurora.tsx`): by night, while a pointer that can hover is over the open sky (not a mountain, not a card or control, not the hero's words where they are drawn), two painted layers glow in across the top, lean a little toward the pointer and ripple; when it leaves they linger, then fade. Phones never download it
- The sun is fixed at the top right, just left of the altimeter's card (hidden on phones, where the massif fills the top of the screen). It does not move with the scroll; only the sky does: dawn to day by day, dusk to midnight by night, from the same two layers and the same one opacity per frame (only their tokens change)
- **Every painting has a night with the day's outline.** The night is painted as an edit of the day (the NIGHT block in `art/scene/README.md`), and processing gives it the day's alpha, so silhouettes match and the reveal never shows a seam. At night the only warm colour in a painting is a camp's own light. The interface over the scene uses tokens (`ink` for line work, which turns pale at night; `shade` for shadows and holes, which stays dark); never write a bare colour into scene markup
- The altimeter (`components/altimeter.tsx`) is the trail in miniature, fixed on the right: "Summit" (`SUMMIT_MARK` in `content/site.ts`) at the top, Start at the bottom, and a two-line mark (year and camp `place`) for every stop; the present one says "Now". The rail is a map, so its ends name places. The stance — `SUMMIT_LINE` — belongs to the scene's summit line and the top of the log on `/cv` (the entry not written yet), and deliberately **not** to the altimeter: the rail and the summit are both in view at the top of the climb, and a stance read twice at once stops being one. A test pins that the altimeter does not repeat it. The marks are plain right-aligned text with a soft halo (`text-shadow-halo`, the card colour, so it flips with the theme); only the stop you are at is an ink pill (pills of different widths side by side looked uneven). Walked is solid ink and still to climb is dotted. Per frame the scroll controller moves only the needle and scales the walked bar (transforms); the lit mark and filled nodes change only when a new stop is reached. On wide screens the list of cards carries `.clear-of-altimeter`, a right padding that keeps right-hand cards clear of the labels at any width; keep it if the labels get wider
- Job cards live in normal flow over the sticky stage (same grid cell), never inside the moving world. Everything is on the card at once, nothing behind a button: role, period and a one-sentence `summary` on top, then a pale "What I did" panel with two or three `highlights`; the company name is the card's only link. A content test keeps the copy short (summary ≤ 150 characters, points ≤ 72). No toggles, overlays, drawers or modals anywhere
- The hero's words float over the painted meadow, so they wear the scene's text halo and sit on a wash of the page colour (`.hero-wash`): a soft one beside the scene on wide screens, a scrim on phones

### The other two pages

- **The climb and the plain list.** The same jobs are told twice: `/` walks them oldest first up the mountain, `/cv` reads them newest first as a field log. They are told in two forms: the climb's cards (`job-card.tsx`) and the log's entries (`log-entry.tsx`: open text on a hairline rail, no card, "Mar 2026 – present · 7 months"). Each page owns the `<li>` around its job, because the climb sizes its stops by tenure (`LEG_SCROLL_LVH`) and the log names a view timeline on each (the year behind it, below). `/cv` opens on the facts a CV is scanned for, then the log, on the page itself; on wide screens the page fades out into the landscape beside it, never under the text. On phones it is just the journal. The dock sends Experience there; the climb links to it from its closing card and from the hero, one quiet dotted line under the social tiles. That line is a signpost, not an apology — it names what is behind it ("Every role, on one page") rather than offering an alternative to a climb the reader has not seen yet, which is what made an earlier version of it read as the hero excusing itself. Plain words on purpose: the reader it is there for is skimming, and a line that leans on the mountain metaphor asks them to decode it first. The recruiter with ninety seconds should not have to find that door behind an unlabelled icon in the dock
- **The printed sheet.** `/cv` is the page that gets saved as a PDF, so it prints as a CV, not as a screenshot of a website: `print:` variants drop the dock, the year behind the log, the rail, the entry not written yet and the trail's foot, the icon-only social tiles and the closing Contact card, and in their place the header prints the three channels as text (`utils/bare-url.ts`) and the degree prints under the jobs (`EDUCATION` in `content/about.ts`, which stays off the screen page). The `@media print` block in `globals.css` sets the page margin, forces the day tokens (browsers keep text colour and drop backgrounds, so a night page would print pale grey on white) and prints every absolute link's address after it
- **The year behind `/cv`.** One place, a meadow at the edge of a larch wood, while the year turns as you read: the page opens on today's season and every hairline passed turns to the next. The seasons are a mood, never a comment on a role, so no picture sits beside a particular job. `scene/seasons.ts` holds it as numbers: seven states (the header, every job, the foot), each carrying **all four seasons as columns** (picture `j` of state `k` is season `j + k`), so the season the year starts in picks a whole column with one CSS rule. That start is written to `<html>` as `data-year-start` by `SEASON_SCRIPT` in `<head>`, beside the theme's script: the page is built once and served for months, so the date cannot come from the build, and `<html>` outlives client navigation. Each entry's `<li>` (and the foot) names a view timeline (`--year-k`), `timeline-scope` on the page's `<main>` lets the backdrop find them, and each state fades in on its hairline and out on the next: CSS scroll-driven opacity on whole layers, no script. Without scroll timelines the year stays on today's season. On wide screens the backdrop is fixed behind the page and is the climb's own world seen from the valley at its foot: the season's sky, the climb's stars, its sun that becomes the moon (`Celestial`), its painted clouds on its wind (`PaintedClouds`), its far ranges and summit (the same paintings as the climb, through `ThemePicture`; the meadow hides their cloud sea but for a band of mist), then the seasonal meadow repeated across the bottom and the grove at the right, cropped by the screen's top and right edges (on screens under about 1280px it slides right so its young larch stays clear of the sheet). Everything at full strength, as on the climb. The header and the log read on the page itself: a veil of the page colour that fades out just right of the 620px column and eases off over the meadow, so the journal is part of the page and the ground still runs edge to edge. The weather falls only right of the list. One kind of weather per season, so it reads at a glance: sakura petals, dandelion seeds and yellow leaves are painted (a kit in `art/cv/raw/weather-{day,night}.png`, packed by `pnpm seasons` into one atlas per theme; each season uses one kind from its row, in its poses, and each particle is cut from the atlas by its background position and size), and winter's snow is the climb's own soft round flake, in CSS. Its motion is generated like the climb's snow (plain numbers, long cycles): petals and leaves sway and turn about a tilted axis, which flips them edge-on as they fall, and seeds rise and rock under their parachutes. It is drawn in the browser (`year-weather.tsx`), for the one season each state shows: on the server it would carry all four, twice. Phones have no room beside the log, so there is no year on them: the backdrop is `display: none`, which downloads none of its paintings. The pictures are CSS backgrounds on purpose, since a picture not displayed is not downloaded: the later states wait for the page to load (`data-year-ready`), only the theme on screen shows, and a theme seen once stays underneath the other (`data-year-seen`), so the day/night switch shows the old paintings until the new ones arrive, never a meadow with no wood. The paintings are `art/cv/raw/{grove,meadow}-<season>-<theme>.png` (prompts in `art/cv/SEASONS-README.md`), processed by `pnpm seasons` into `public/seasons/` and `scene/seasons.json`: keyed, each night given its day's outline, the magenta the painter reflected into thin tufts and grass cleaned (only the pixels that carry it are repainted: a twig a few pixels thin is all edge, and repainting every edge pixel smears colour along it), the meadow made a seamless tile, and the colour under transparent pixels filled before WebP encodes it (WebP keeps colour at half resolution, and a hidden colour bleeds into thin twigs as fringes). Reduced motion: the year steps at the same hairlines, and no weather
- **`/about`: what's ahead** (`app/about/page.tsx`, `scene/about.ts`, rules under "/about: what's ahead" in `globals.css`). The summit's page looks forward, not back. It opens on the climb's own sky at the visitor's time of day: `DAYPART_SCRIPT` in `<head>` writes `data-daypart` (morning, midday, evening, night) to `<html>`, like the season's script, and the opening's gradient mixes the dawn and day tokens by it (by night those tokens are dusk and midnight), with the climb's clouds on its wind and, by night, its stars; no sun or moon there, the sun is the ending's. The header stands on that sky in the page's ink (`PageHeader`, below), with "Email me" and the way back; everything read is on the page. Then Background (the About text, with every fact beside it), How I work (the opinions as statements with how often they hold in words, `holdsInWords`, and a five-step scale; the week as one proportion bar, the accent on its largest share) and Skills (plain lists, logos beside them, no pills), each section's name in a margin that stays in view. It ends at Contact, one screen and the page's last, nothing pinned: the card near the top, a band of open sky, and the next range along the bottom edge. The range is one painting in three lights with one outline (`range-sunrise`, `range-day`, `range-night`); as the screen scrolls in (a view timeline on the section, `entry` range), dawn becomes morning and the climb's `Celestial` comes up from behind the right-hand ridge (by night, dusk becomes midnight and the moon rises). How tall the range stands is measured on the painting (`SUMMIT`, `CLOUD_LINE` in `scene/about.json`) and, since the range spans the screen, set in `cqw` of the section, so the card never overlaps the summit at any width. The one easter egg: making contact (Copy or "Email me", marked `data-contact-action` in `contact-rows.tsx`) sets `data-contact` on the section (`contact-signal.tsx`), and a small saucer comes in from high in the sky, hovers in the band under the card, blinks its running lights twice (glows at the points the script found on the painting) and swings back up into the sky: eight seconds, once, three wrappers so its path curves; it sits between the sky and the range, so the peaks can hide it. Reduced motion: the sun steps, the saucer only fades in and out. Phones: just the words. The paintings are `art/about/raw/ahead/land-{sunrise,day,night}.png` and the top-left piece of `art/about/raw/ufo-{day,night}.png` (prompts in `art/about/`), processed by `pnpm about` into `public/about/` and `scene/about.json`

### Across the site

- **Day and night.** `data-theme` on `<html>` is the only switch. The inline script from `lib/theme.ts` sets it in `<head>` before the first paint (the stored choice, else the system's), so there is no flash; `<html>` has `suppressHydrationWarning` for that reason. `color-scheme` follows it. There is no theme library
- **The reveal** (`switchTheme()` in `lib/theme.ts`, rules under "Switching day and night" in `globals.css`): a view transition keeps the old page still and shows the new one through a soft-edged circle that grows from the toggle (`--reveal-r`, animated from script, ease-out, `THEME_REVEAL`). The new view is the live page, so things in the sky change on the wave: any element with `data-wave` gets a `--wave-delay`, when the circle's edge reaches it, and its own CSS transitions wait for it. The sun becomes the moon that way (`.celestial`: the earth's shadow slides over it from the lower left), and each star comes out that way (`.star`, with a lag: the brightest first). Anything new that should change with the night in the sky follows the same pattern. Reduced motion: the browser's own cross-fade, no circle, no wave. No view transitions: an instant switch, with the wave still timing the sky
- **Moving between pages** (`components/trail-link.tsx`, the `<ViewTransition>` around every page in `app/layout.tsx`, rules under "Moving between the pages" in `globals.css`). The three pages are three heights on one mountain: `/cv` the valley, `/` the climb, `/about` the summit. Every link between them is a `TrailLink`: next/link with the navigation run in a transition named for its direction (`addTransitionType`: `trail-up`, `trail-down`). Going up, the page leaves upward and the next rises in from below, as the climb's cards move when you climb; going down, the reverse. The old page leaves in 240ms with a slight haze, and the new one eases in over 560ms on `--ease-soft`, a beat later. Only the pictures move: the two pages' boxes are never morphed into each other. The dock is a `<ViewTransition>` of its own (`dock-still`), or the page's picture would cover it while it moves. React names these boundaries only during its own transitions, so the day/night reveal (a plain `document.startViewTransition`) is untouched. A link to the page you are on, a modified click or another site is left to the link itself. `ViewTransition` and `addTransitionType` come from the React that Next bundles with `experimental.viewTransition` (types: `react-canary.d.ts`). Reduced motion: a plain cross-fade
- **Pictures on the still pages** (`ThemePicture`, `.theme-art` in `globals.css`): a day and a night picture as CSS backgrounds, only the theme on screen displayed, so only its picture downloads; a theme already seen stays underneath the other while the new one arrives. Use it for any painting outside the climb's stage
- The root must not get `overflow-x: hidden` (it would become a scroll container and break `position: sticky`); `body` uses `overflow-x: clip`
- **One header for `/cv` and `/about`** (`components/page-header.tsx`). The two pages open on the same block in the same type: the page's name as the eyebrow, in the dock's word for it (`dockLabel()`), since the dock shows only icons; the title at the `page` size (the `hero` size is the climb's alone, where the site makes its first impression); one line under it; the page's actions; and, on `/cv` only, its facts between two hairlines. Only the words differ. A fact is read in one header only: `/cv` carries the three a CV is scanned for, and `/about` lists them all beside its Background text instead of repeating them at the top. The eyebrow does not print: on paper the sheet is the CV, and the role prints under the name
- The dock's About goes to the top of `/about`, its header, not to a section; a page's own item is lit on that page until one of its sections (Contact) is under the middle of the screen, so one item is lit at a time. The dock holds the three pages and the one action, nothing else: a section is reached by reading on (Skills was taken out for that reason), and with four items Home fits at every width
- The dock is icon-only, so names come from `aria-label`; bubbles and icons are `aria-hidden`. Tests query by role and name. The day/night switch sits after a hairline, outside the `Sections` landmark (a setting, not a place); its icon (a moon by day, a sun at night: where the click takes you) is picked by CSS so it is right from the first paint
